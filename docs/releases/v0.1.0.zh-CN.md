# StateReceipt v0.1.0（简体中文）

[English](v0.1.0.md) | [Español](v0.1.0.es.md)

StateReceipt v0.1.0 是 StateReceipt 规范草案与 Python 参考实现的第一个公开里程碑。

StateReceipt 用于记录 AI 辅助工作在某一时间点的状态声明，以及与这些声明显式绑定的 Evidence、工件快照、有效性依赖和确定性的 freshness/staleness 检查。它关注的问题很具体：**之前记录的工作状态声明，在当前工件状态下还有哪些仍被原有证据支持？**

## 主要内容

- StateReceipt v0.1 JSON Schema 与英文正式规范。
- 显式 Claim–Evidence 绑定，以及 SHA-256 / SHA-512 工件快照。
- 确定性的 Claim evaluation，包括依赖感知的 `stale` 行为。
- 跨平台 CLI：`init`、`capture`、`validate`、`validate-chain`、`verify`、`inspect`、`diff`。
- 不可变 Receipt 生命周期，可通过 predecessor ID 建立直接续接关系，并验证本地 self-reference / cycle / duplicate ID。
- 默认安全的验证：除非同时提供 `--replay --trust-receipt`，否则不会执行 Receipt 中的命令。
- 5 分钟端到端 Quick Start，以及 English / 简体中文 / Español 第一方文档。
- Python、FPGA/Verilog、MATLAB 三类示例 Receipt。
- 可选的 in-toto Statement / DSSE 互操作说明，不自创 StateReceipt 密码学机制。
- Ubuntu / Windows / macOS × Python 3.11–3.13 CI。
- wheel 与 sdist 构建、干净安装及 packaged schema 检查。

## 重要语义

`stale` **不等于** Claim 为假。它表示针对旧快照捕获的 Evidence 已不能继续可靠支持当前状态，需要重新评估 Claim。

结构合法的 Receipt 也不能证明 producer 身份。v0.1.0 不定义签名或 producer authentication。

## Replay 安全

普通验证不会执行命令：

```bash
statereceipt verify receipt.yaml
```

单独使用 `--replay` 会被拒绝。真正执行必须显式确认：

```bash
statereceipt verify receipt.yaml --replay --trust-receipt
```

StateReceipt **不是 sandbox**。`--trust-receipt` 只表示调用者已检查 Receipt 并接受执行风险，不代表身份认证或安全保证。

## 生命周期

Receipt 是不可变的时间点工件。后续 Receipt 可以声明一个直接 predecessor。本地链验证器可以发现重复 ID、自引用和 cycle，同时允许 external/unresolved predecessor。

```bash
statereceipt validate-chain sr-a.yaml sr-b.yaml sr-c.yaml
```

## 互操作

探索性互操作 profile 将完整 StateReceipt 文档放入 in-toto Statement 的 predicate，并把工件 digest 投影到 subject。如果需要 authenticity，可以由外部实现使用 DSSE 包装 Statement。

不签名的本地 Receipt 仍完全符合规范。即使签名有效，也只是根据外部 trust policy 对字节进行认证，并不证明自然语言 Claim 为真或工作本身正确。

## 明确不做

StateReceipt v0.1.0 不是：

- AI 持久记忆数据库；
- RAG / 向量系统；
- 聊天历史同步格式；
- agent orchestrator 或 scheduler；
- 进程 / 网络 / 文件系统 sandbox；
- 密码学签名系统或 PKI；
- AI 生成 Claim 的自动真值裁判。

## 兼容性

- Python：3.11、3.12、3.13
- CI 测试系统：Ubuntu、Windows、macOS
- 许可证：Apache-2.0

这是 pre-1.0 版本。v0.1 规范仍是草案，在 1.0 前仍可能发生明确记录的不兼容变化。
